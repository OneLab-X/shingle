# Multi-language sites

Read this when `languages` has 2+ entries. Output: `/<lang>/` copies of every page, a language
switcher, hreflang tags, translated interface text. Single-language sites ignore all of this.

## Setup (in this order)
1. `languages` in business.json: first entry is the default (the language the owner wrote the facts in).
2. `python3 SK/scripts/sync.py <site> --init-i18n`: adds `src/pages/[lang]/index.astro` and a
   language-neutral `404.astro`, removing the single-language ones only if untouched.
3. Draft `translations.<lang>` (see `business-schema.md`). `sync.py` prints which prose fields are
   still untranslated and which languages are still `draft`.
4. Build pages under `src/pages/[lang]/` with `export const getStaticPaths = langPaths;` and read
   facts with `getSite(lang)`, interface text with `useT(lang)`, links with `lurl("/x/", lang)`.
   One page file serves every language: do not copy pages per language.
5. `npm run build`, then `audit_site.py dist --strict`: it checks hreflang, canonicals, `lang`,
   page parity between languages, the root redirect and the sitemap alternates.

## Writing the draft translation
- Translate prose only: tagline, descriptions, menu/product descriptions, FAQ, notes, headings.
- Copy unchanged: prices, phone numbers, email, URLs, the business name, people's names. The
  validator rejects changes to these.
- Keep it the same length and structure as the original: same number of list items, same keys.
- Write natural local copy, not word-for-word. If unsure of a term (legal, medical, food
  allergens), keep the default-language wording and add a TODO instead of guessing.
- Leave `review: "draft"`. Never set `"reviewed"` yourself: only the owner (or their translator) does.
- Do not translate `decisions.*` except `decisions.cta.label`.

## Interface text
Buttons, day names, "Open now", the skip link etc. come from `references/ui-strings/<lang>.json`
(en, pt, es, fr, de, it). Other languages fall back to English interface text and the validator
warns: adding one is a single file, see `docs/adding-a-language.md`. Right-to-left languages
(ar, he, fa, ur) are not supported by the templates yet.

## What the template does for you
- `<html lang dir>`, absolute reciprocal hreflang alternates + `x-default`, self-canonical,
  `og:locale` + `og:locale:alternate`, sitemap alternates, per-language JSON-LD.
- Language switcher (header and footer) linking to the same page in each language.
- `/` redirects to the default language (static, works on every host).
- Day names, hours and open-now status in the page's language.

Photos: alt text is the only translated part of `images`. `import_images.py --apply-alt` writes it to
`translations.<lang>.images[i].alt` (same position as `images[i]`); `subject` slots stay as written.
